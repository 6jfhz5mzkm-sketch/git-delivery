# 发布到公共托管：通用步骤

> 仅在需要把仓库发布到公共托管（GitHub/GitLab 等）时读本文件。
> 具体平台命令以目标平台文档为准；下列步骤与平台无关。

## 1. 确定导出范围
- 明确这次发布**带哪些目录**，以及**明确排除**哪些（内部规划文档、任务单、证据、备份、
  内部部署方案、一次性产物）。
- 用版本库导出而不是拷贝工作区，避免带入未提交的半成品：
  `git archive HEAD <dir1> <dir2> | tar -x -C <export-dir>`

## 2. 排除敏感项（逐项核对，不靠印象）
- 真实 `.env`、证书、私钥、token
- 运维信息：服务器地址、部署根路径、内部主机名、SSH 参数
- 组织信息：内部邮箱域、内部系统 ID、open_id
- 内部工具脚本（含真实凭据或内部路径的）
- 判断依据：`git grep -n` 扫描关键词，而不是「应该没有」

## 3. 占位符替换
- 服务器地址 → `<SERVER_IP>`；部署路径 → `<DEPLOY_ROOT>`；
  内部邮箱 → `<INTERNAL_EMAIL>`；密钥类 → 直接删除并改读环境变量
- 逐行核对改动，确认**只动了注释/文案/字符串**，没有改动逻辑（行数不变是好信号）
- 改写前先探测源文件编码（严格 UTF-8 校验），非 UTF-8 先解码再以 UTF-8 写出，
  否则老编码文件会变成乱码

## 4. 提交身份
- 公共仓用托管平台的 noreply 邮箱，**不要让内部域邮箱进入公开提交元数据**
- 只对本次发布使用，不改全局配置：`git -c user.name=… -c user.email=… commit …`

## 5. 推送前
```
git push --dry-run origin <branch>
```

## 6. 推送后独立复核（强制）
- **全新浅克隆**到临时目录：`git clone --depth 1 <url> <tmp>`
- 在克隆里跑泄漏扫描：服务器地址、内部路径、完整 open_id、密钥前缀、私钥标记、内部邮箱
- 核对文件数、关键目录是否存在、敏感文件是否 0
- 扫描结果全部 0 才算完成；有命中 → 立刻处理，**不要**只删文件了事（历史里可能还在）

## 7. 泄漏已经发生时的处置
- 立即轮换凭据（不是删文件）；
- 判断是否在历史中（`git log -S<关键词>`），必要时重写历史 + 强推，并在仓库说明；
- 向用户报告事实、影响范围与已采取的处置，不隐瞒。
