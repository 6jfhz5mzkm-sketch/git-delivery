# git-delivery

给 AI agent 用的 Git 提交纪律技能：**到关键节点主动提醒提交 → 出计划等你授权 → 按项目规则原子提交 → 回报可反查的状态**。

## 安装

1. 把整个 `git-delivery/` 目录放进你的技能目录：
   - DSH：`~/.dsh/skills/git-delivery/`（Windows：`C:\Users\<你>\.dsh\skills\git-delivery\`）
   - 其它 harness：放进它约定的 skills 目录，保持 `SKILL.md` 在目录根。
2. 重开会话（catalog 会重新扫描）。不需要装依赖、不需要联网。

## 怎么触发

在对话里说出下列任一意图即可，不需要记命令：

| 你想干什么 | 这样说 |
|---|---|
| 提交 | 「提交」「存一下」「备份当前版本」 |
| 发布 | 「推上去」「上传到仓库」「打个 tag」 |
| 拿不准 | 「现在该提交吗」「改动这么大是不是该重来」「从哪个版本改最省事」 |
| 出事故 | 「提交错了」「误删了」「reset 之后还能救吗」 |
| 新项目 | 「新项目开工」「要建 .gitignore」 |

技能不会自己提交——**必须你明确说「提交」**。它会先给你看计划和验证结果。

## 让某个项目以后都生效（§14 接入片段）

技能是「按需加载」的文本，**没有任何办法保证它在某一轮自动出现**——这是能力边界，不是配置问题。
它能做到的是：一旦被加载，就把积压一次讲清；以及一次加载之后，把规则固化到项目里。

想让某个项目**以后每次会话都提醒**（不再依赖本技能被加载），两个办法，都需要有人执行一次：

**办法 A**：在该项目里对 agent 说一次「检查一下这个项目有没有 git 提交规则」。
它会加载本技能、检查规则文件（`AGENTS.md` / `CLAUDE.md` / `CONTRIBUTING.md`），没有就问你一句要不要加。

**办法 B（手动）**：把 `SKILL.md` §14 里那段 5 行 markdown 复制进项目规则文件的**已有 Git 章节**。
**不要新增一个平行章节**——两处规则打架时没人裁决。
项目没有任何规则文件时，本技能**不会替你新建**（避免侵入），只在回复里告诉你有这个选项。

## 最佳使用方案

### 方案一：日常项目（零配置，推荐起步）
1. 装到技能目录（见「安装」），重开会话。
2. 干活时说到「做完了 / 可以了 / 先这样」就够——**不必专门说「提交」**，这类说法本身就是节点信号。
3. 它会给出事实：改了几个文件 / 验证过没有 / 「要提交就说一声」，不问选择题。
4. 你说「提交」，它按目标项目的规则拆成原子提交，并回报可反查的 hash 与状态。

适合：个人项目、一次性任务、不想改项目文件。

### 方案二：长期项目 / 多 Agent 并行（做一次强绑定）
在方案一基础上增加一次性接入：
1. 在该项目里说「检查一下这个项目有没有 git 提交规则」。
2. 它会把 `SKILL.md` §14 的 5 行合并进项目规则文件的**已有 Git 章节**（不会新建文件）。
3. 之后该项目**任何会话、任何 agent** 都会提醒，不再依赖本技能被加载。

适合：会持续几个月、多会话、多 Agent 的项目。

### 方案三：团队仓库
- 先让它读项目自己的规则（§3 规则源探测），**团队规范优先**，本技能只做兜底。
- 不要用 §14 覆盖团队已有规则，只补充缺失项——两处规则打架时没人裁决。

### 三条硬建议
1. **按闭环提交，不按文件数**：拆分裂据是「能独立 revert」，不是「一天一次」。
2. **破坏性操作单独确认**：`reset --hard`、`clean -fd`、`push --force` 各要一次明确指令，不接受批量授权。
3. **别指望它自动盯着你**：未被加载时它不存在；长期项目请走方案二。

## 典型对话

```
你：这个功能做完了，你看下
它：（节点自查）改动了 3 个文件（+120 / −8），验证未跑；要提交就说一声
你：提交
它：（四段汇报 + 拆分计划）拟拆 2 笔：① feat(core): … ② docs: …
你：可以
它：COMMITTED（hash / git log 反查一致 / 工作区状态 / 推送情况）
```

## 边界（重要）

- **无法保证被加载**：宿主决定是否加载，技能自身无法注册、定时、订阅事件或改宿主配置。
  未被加载的那一轮，它不存在——不要把它当成「会一直提醒」的守卫。
- **没有强制力**：它只是文本。真正的拦截靠 harness 审批、服务端保护分支、本地 hook。
- **无状态**：不写任何「上次执行」记录，每次从 git 现状重算；允许重复提醒。
- **不携带脚本**：只调用环境里已有的 `git`，不下载、不装依赖。
- **不含任何项目信息**：提交风格、rule、验证命令全部从目标项目现取。

## 快速自检

装好后随便找一个仓库，对 agent 说「现在该提交吗」。
正常表现：它只做只读检查，输出「提交节点」提醒或「当前无改动」，**不会**直接提交任何东西。
